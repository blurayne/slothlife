# Building a TWA (Trusted Web Activity)

A TWA is the Android wrapper that lets a PWA install as a
native app — same UI as the website, but distributable through
the Play Store. Slothlife's TWA wrapper is generated by
[Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap)
from `twa-manifest.json` and signed with an Android keystore.

You have two paths:

1. **CI build** — push to GitHub and let
   [`build-android.yml`](.github/workflows/build-android.yml)
   produce the `.apk` / `.aab` as workflow artifacts. Best for
   one-off builds.
2. **Local build via mise** — run [`mise.toml`](mise.toml)
   tasks. Best for iterating on icons / keystore / branding.

Either way the **same** `twa-manifest.json` is the source of
truth.

## Prerequisites for a local build

| Tool | Why | Version |
|---|---|---|
| Node | runs Bubblewrap | 20+ |
| JDK (Temurin) | Bubblewrap drives Gradle | 17 |
| Android SDK + cmdline-tools | Gradle needs the Android platform | recent |
| `librsvg2-bin` | renders icons from `assets/favicon.svg` | any |
| `imagemagick` | composites the maskable icon | any |
| `keytool` | ships with the JDK; debug keystore | n/a |
| `mise` | runs the tasks below | 2024+ |

`mise` resolves the `node` and `java` versions automatically
(`[tools]` block in `mise.toml`). The Android SDK must be
installed separately — Android Studio is the easiest path; CLI
folks can use [`commandlinetools-linux`].

[`commandlinetools-linux`]: https://developer.android.com/studio#command-line-tools-only

Set `ANDROID_HOME` (or `ANDROID_SDK_ROOT`) to the SDK root
before running the build task.

## Steps

### 1. Render the icon set

The web manifest's icons are PNGs rendered from
`assets/favicon.svg`. Bubblewrap fetches them from `iconUrl`
and `maskableIconUrl` in `twa-manifest.json` to bake them into
the APK as drawable resources.

```sh
mise run twa:icons
```

Writes `icons/icon-192.png`, `icons/icon-512.png`, and
`icons/icon-mask-512.png`.

### 2. Generate a signing keystore

```sh
mise run twa:keystore
```

Writes `android.keystore` with throwaway debug passwords
(`android` for both `storepass` and `keypass`). The same
defaults are baked into `twa-manifest.json`'s `signingKey`
block, so Bubblewrap and `keytool` stay in lockstep.

For Play Store distribution, **replace** this step with a
real keystore (see "Production signing" below). The debug
keystore is fine for sideloading APKs onto your own device.

### 3. Build the TWA

```sh
mise run twa:build
```

Behind the scenes:

- `npm install` populates `node_modules/@bubblewrap/cli`.
- A local HTTP server on `127.0.0.1:8765` serves the icons so
  Bubblewrap doesn't need to round-trip through the deployed
  Pages site (which is racy on fresh deploys). The two
  icon-URL fields in `twa-manifest.json` are rewritten to
  localhost just for this step, then restored.
- `bubblewrap update --skipVersionUpgrade` regenerates `app/`,
  `build.gradle`, `settings.gradle`, `gradle/`, and `gradlew`
  from `twa-manifest.json`.
- `bubblewrap build --skipPwaValidation` runs Gradle and
  produces `app-release-signed.apk` and
  `app-release-bundle.aab` at the repo root.

The `twa:build` task `depends = ["twa:icons", "twa:keystore"]`,
so a fresh checkout can run `mise run twa:build` directly and
the icons + keystore steps run automatically.

### 4. Print the signing-key SHA-256

```sh
mise run twa:sha256
```

Paste the SHA-256 fingerprint into a Digital Asset Links file
at `https://blurayne.github.io/.well-known/assetlinks.json`.
Until that file is hosted at the **apex** of the domain, the
TWA shows the Chrome address bar inside the app — Slothlife is
deployed at `/slothlife/`, not the apex, so the assetlinks file
needs to live one level up from the deploy.

The file's shape (replace the SHA below with your own
fingerprint):

```json
[{
  "relation": ["delegate_permission/common.handle_all_urls"],
  "target": {
    "namespace": "android_app",
    "package_name": "io.github.blurayne.slothlife",
    "sha256_cert_fingerprints":
      ["AB:CD:EF:01:23:45:..."]
  }
}]
```

See [Verify Android App Links] for the full setup and
verification flow.

[Verify Android App Links]: https://developer.android.com/training/app-links/verify-android-applinks

### 5. Sideload (or upload to Play Console)

```sh
adb install app-release-signed.apk
```

For Play Store distribution, upload `app-release-bundle.aab`
to the Play Console and follow the standard release flow.

### Cleanup

```sh
mise run twa:clean
```

Removes `icons/`, `app/`, `build/`, `gradle/`, `*.apk`,
`*.aab`, `manifest-checksum.json`, and `android.keystore`. All
of those are gitignored.

## Production signing

For Play Store releases, replace `mise run twa:keystore` with:

```sh
keytool -genkeypair \
  -alias android \
  -keystore android.keystore \
  -storepass "$REAL_STOREPASS" \
  -keypass "$REAL_KEYPASS" \
  -dname "CN=…,O=…,C=…" \
  -keyalg RSA -keysize 2048 -validity 10000
```

Store both passwords in your secret manager. Set
`BUBBLEWRAP_KEYSTORE_PASSWORD` and `BUBBLEWRAP_KEY_PASSWORD`
in the build env (the mise `[env]` block sets them to the
debug values; override locally with a `.mise.local.toml` or
shell exports for production builds).

The CI workflow (`build-android.yml`) uses the same throwaway
keystore — fine for sideloadable artifacts, **not** suitable
for Play Store upload. For production CI, gate the workflow
behind a manual approval and pull the keystore + passwords
from `ANDROID_KEYSTORE_B64` / `ANDROID_KEYSTORE_PASS` /
`ANDROID_KEY_PASS` repository secrets.

## CI build

GitHub → **Actions** tab → **Build Android (TWA)** → **Run
workflow**.

The workflow uploads `slothlife-android.zip` containing the
APK + AAB. Same mechanics as the local build — only the
runner environment differs.

## How the TWA points at the web app

| Manifest field | Effect | Baked into APK? |
|---|---|---|
| `host` | Origin for the TWA's full-screen browsing | ✅ |
| `webManifestUrl` | URL fetched at first launch for `manifest.json` | ✅ |
| `fullScopeUrl` | Bound for in-TWA navigation | ✅ |
| `startUrl` | First page shown when launching the app | ✅ |
| `iconUrl` | Fetched at build time, baked as drawable | bitmap only |
| `maskableIconUrl` | Same | bitmap only |
| `signingKey` | Used by Bubblewrap to sign the APK | ✅ |

So `host`, `webManifestUrl`, `fullScopeUrl`, and `startUrl`
are runtime references against the deployed PWA — change
them and you must rebuild the APK. `iconUrl` and
`maskableIconUrl` are fetch-time only and only the bytes
end up in the APK.
